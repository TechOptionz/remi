# Website (Next.js) — repo root
The live website is the Next.js app at the repo root (App Router, TypeScript, prerendered pages plus one API route, deployed on Vercel). The old hand-written HTML site was removed once the migration was complete (it remains in git history).

Commands (run from the repo root): `npm run dev` (local preview), `npm run build` (must pass before committing), `npm run typecheck`, `npm run search-index` (rebuild only the search index from `.next/server/app`), `npm run llms` (rebuild only `public/llms.txt`).

## Where things live
- `src/app/<route>/page.tsx` — one file per page. It only lists that page's sections in order and sets the page title/description. Routes: `/`, `/perspectives`, `/about-remi`, `/ideas-models`, `/programs`, `/invite-remi`.
- `src/app/layout.tsx` — fonts, global CSS, and the chrome on every page: Header, Footer, ChatWidget, `ScrollToTop` (every page change opens at the very top, except `#id` links and back/forward) and `SmoothScroll` (Lenis: eased wheel/trackpad scrolling site-wide; same-page `#id` links glide to their section, honouring `scroll-margin-top`; touch keeps native scrolling; off under reduced motion). Code that moves the page uses `scrollToY` / `scrollToEl` from `src/lib/smooth-scroll.ts`, not `window.scrollTo`, so Lenis and the window agree on the position.
- `src/components/<page>/` — one component per visible section (`home/`, `about/`, `invite/`, `ideas/`). Section copy is written inline in its file: to change wording, edit that section's file.
- `src/components/home/hero/` — the home hero: `Hero.tsx` (picks the variant), `variants.tsx` (layouts A, B, C, C1, C2/C3, D), `parts.tsx` (shared title, buttons, Vimeo frame).
- `src/components/layout/` — Header, VariantsMenu, SiteSearch, Footer. `src/components/shared/` — ChatWidget, NewsletterForm, SocialLinks, TrustmeLevels.
- `src/content/site.ts` — anything shared or list-like: nav links, header CTA, hero copy, hero/palette options, social links, footer copy, form dropdown options, T.R.U.S.T.M.E. levels, Vimeo ID. `src/content/chat.ts` — chat copy, scripted replies, keyword matching.
- `src/lib/site-state.tsx` — palette + hero variant state (localStorage, `?palette=` / `?hero=`). `src/lib/forms.ts` — `usePresetSelect` and `submitLead`, the single place all forms submit: it POSTs to `src/app/api/lead/route.ts`, which sends the team a notification through Resend, auto-replies to enquiries and invitations, and adds sign-ups and invitations as Resend contacts sorted into segments (`LISTS` / `PRODUCT_LISTS` in the route; each segment is found or created in Resend by name, so nothing is set up by hand): the topic lists (Leadership, Business, Personal development, Consultative sales, Relationships), "Invite Remi", and "Waitlist — Rebel Yell / The Shift / Selling from Stage". Invitations and the Rebel Yell waitlist join only their own segment, not the general `RESEND_SEGMENT_ID` list; enquiries and feedback are not added. Env vars in `.env.example` (`RESEND_API_KEY`, `RESEND_FROM`, `RESEND_TO`, optional `RESEND_SEGMENT_ID` and `RESEND_SEGMENT_ID_<LIST>` overrides; set them in `.env.local` and in Vercel). `submitLead` resolves to an error message (or null); each form disables its button while sending and shows `.form-error` on failure. A new form should call `submitLead` (or `sendLead` with plain fields) with one of its five kinds. `feedback` is reader feedback, in place of public comments (Remi asked for comments; the team recommended against them, Oct 2026): every article ends with "Was this helpful?" (`shared/Helpful.tsx`: votes are counted in Upstash Redis — the Vercel Marketplace store `remi-helpful`, env `KV_REST_API_URL` / `KV_REST_API_TOKEN` — through `/api/helpful` and `lib/helpful.ts`, one per connection per article per day, remembered in the browser, not emailed; the article shows "N readers found this helpful" once `SHOW_FROM` (1) has said yes, under the buttons and under the Share drop-down at the top (`HelpfulCount`, which updates when the reader votes); the team's totals for every article are on the private `/stats?key=<STATS_KEY>` page, noindex and kept out of the sitemap and robots), share links as round icon buttons (`shared/ShareLinks.tsx`: the device's share sheet, copy link, email, LinkedIn, Facebook, WhatsApp, as plain links with no third-party scripts; the same targets open from the "Share" drop-down beside the breadcrumbs at the top, `shared/ShareMenu.tsx`), "Ask Remi a question" (`shared/AskRemi.tsx`, a private form; name and email optional) and a sign-up to the article's list (`SegmentCta`, topic → list in `SEGMENT_OF`); Perspectives has the same private form after the archive (`#ask`, with a dropdown of `CONVERSATIONS`), since episodes play on YouTube. Styles `styles/reader.css` (`.rf-*`). Forms can carry a hidden `fax` honeypot; `/api/lead` silently drops anything that fills it. Every notification's subject names that form's own topic (`topicOf` in the route): the product for a "tell me when it's ready" form, the list for a topic sign-up, the interest / invitation for enquiries and invitations, and otherwise the page it was sent from (`submitLead` adds `page` and `url` to every submission). Only the Rebel Yell form, which names no product, is titled "Rebel Yell waitlist".
- `src/styles/` — plain CSS, one file per area, imported in order by `index.css` (order matters). Colours come from the palette tokens in `tokens.css`; `ideas-models.css` uses fixed colours by design.
- `public/assets/` — images, referenced as `/assets/...`.

## Conventions
- Header drop-downs come from `children` in `NAV` (`content/site.ts`); children with a `group` show under that label. The Ideas & Models drop-down is the overview plus every card of `GLANCE` in `content/ideas.ts` that links to a chapter page or a section of the overview (`#part-N` becomes `/ideas-models#part-N`), so a new card there appears in the menu; it lays the groups out in two balanced CSS columns (`.nav-sub--groups` in `styles/header.css`). The footer lists the top level only.
- Site search (header button, Ctrl/⌘ K or "/"): `components/layout/SiteSearch.tsx`, matching in `lib/search.ts`, styles in `styles/search.css`. The index is not hand-written: `npm run build` runs `scripts/search-index.mjs`, which reads every prerendered page in `.next/server/app` and makes one entry per h1–h3 heading (linking to the heading's id or its nearest section id), writing `public/search-index.json` (git-ignored; served by Vercel after the build and by `npm run dev`). New pages and sections are searchable after the next build; give a section a heading (and ideally an id) to make it findable. Suggestion chips are `SEARCH_SUGGESTIONS` in `content/site.ts`.
- Add a section: create `src/components/<page>/<Name>.tsx`, add it to that page's `page.tsx`, put its CSS in the matching file in `src/styles/`.
- Add a page: create `src/app/<route>/page.tsx` with `metadata`, add it to `NAV` in `src/content/site.ts`.
- Components are server components unless they need state/events; those start with `'use client'`.
- Internal page links use `next/link` with clean routes (`/about-remi`, not `.html`); same-page anchors use plain `<a href="#id">`.
- Preset a form from any link: `data-interest="Speaking"` (homepage enquiry form, or `/?interest=Speaking#contact`) and `data-invite="Speaking"` (invite form, or `/invite-remi?invite=Speaking#invite-form`). Values must match `INTERESTS` / `INVITATIONS` in `content/site.ts`.
- Sitemap, robots and llms.txt are generated, not hand-written. `src/app/sitemap.ts` lists every page folder plus each product and article (top-level nav pages weigh more, the designed sales pages in `LANDING_SLUGS` (`content/products.ts`, which also types `LANDINGS` in `app/products/[slug]/page.tsx`) a little less, other products and the privacy policy less). Articles carry their own `date` as lastmod (the `/articles` hub the newest one), other pages the build date; `/books` lists its covers and each article its card image as sitemap images; a page with nothing on it yet is held back in `HELD_BACK` and set `noindex` on the page itself (Reviews, while `REVIEWS` is empty). `src/app/robots.ts` allows everything but `/api/`. `npm run build` runs `scripts/llms-txt.mjs`, which writes `public/llms.txt` (git-ignored) from the built sitemap: each page's `<title>` and meta description, grouped into sections by address and ordered as their hub page links to them — so a page's metadata description is also its llms.txt line.
- Redirects live in `next.config.mjs`: old `.html` addresses and the previous Wix site's URLs (`/post/…` show notes → the Perspectives archive, `?q=<guest>` when the episode is in `CONVERSATIONS`, else `?topic=<slug>`; `/blog/…`, `/workwithremi`, `/plans-pricing`, `/event-details/…` etc.). The archive reads `?q=` and matches `?topic=` by letters only, so `ideas-meaning` = "Ideas & meaning". `/privacy-policy` (`components/legal/PrivacyPolicy.tsx`, `styles/legal.css`) is the footer's Privacy link.
- Use plain `<img>` (no image optimisation). Keep existing class names — the CSS targets them.
